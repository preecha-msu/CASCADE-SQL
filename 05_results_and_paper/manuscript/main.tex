\begin{abstract}
Serverless Function-as-a-Service (FaaS) platforms coupled with managed Cloud Database-as-a-Service (DBaaS) backends confront an unresolved security-systems tension: deterministic signature Web Application Firewalls (WAFs) suffer from crippling false-positive rates on modern Object-Relational Mapping (ORM) queries and syntactic evasion, whereas monolithic deep neural detectors impose multi-millisecond CPU latency, cold-start overhead, and vulnerability to prefix-padding and Algorithmic Complexity Denial-of-Service (DoS). This study presents \textbf{CASCADE-SQL}, a hardened two-stage cascaded ONNX INT8 proxy for real-time SQL injection (SQLi) defense across PostgreSQL and MySQL workloads. Every incoming query first traverses an $O(1)$ byte-length and $O(L_{\max})$ parenthesis-depth pre-parser guard before entering Stage-1, a strided multi-window character CNN-BiLSTM fast filter ($W=256, S=192$; 145,249 parameters). Confident single-window queries exit immediately, while uncertain gray-zone ($\tau_{\text{low}}^*=0.05 < p_1 < \tau_{\text{high}}^*=0.65$) and multi-window hotspot queries escalate to Stage-2, a comment-unwrapped \texttt{sqlglot} Abstract Syntax Tree (AST) structural and 4-head Self-Attention verifier (106,177 parameters). Across 50,460 deduplicated queries (42,667 canonical AST templates with 0\% cross-split template overlap), 5-fold group-isolated cross-validation yields 0.9989 $\pm$ 0.0002 F1 and 0.9998 $\pm$ 0.0001 ROC-AUC. Hardened CASCADE-SQL outperforms OWASP CRS v4, LibInjection, TF-IDF+GBDT, 2-layer BiLSTM-Attention, and a 4-layer Subword SQL Transformer—matching Transformer adversarial recall (99.63\% vs.\ 99.76\%, McNemar $p=0.1338$) while running $4.74\times$ faster in a $7.48\times$ smaller 721.8~KB footprint. Furthermore, CASCADE-SQL achieves 0.00\% FPR on 2,000 hard-benign ORM queries (vs.\ 80.0\% for CRS v4), 99.1--100.0\% recall against 256B--4KB prefix-padded tail injections, significant resilience under 100-query grey-box WAF-A-MoLE attacks ($p=1.24\times 10^{-12}$), 549.0~RPS live HTTP proxy throughput at 0\% error, and an 81.13\% Google Cloud Run compute cost reduction.
\end{abstract}

\section{Introduction}
Cloud-native architectures increasingly pair stateless serverless containers (e.g., Google Cloud Run, AWS Lambda) with managed relational databases \cite{jonas2019serverless,baldini2017serverless,eismann2021serverless_cost}. Inline SQLi inspection within such environments must satisfy four simultaneous operational constraints: sub-millisecond single-vCPU latency, fast container cold-start \cite{lin2020faas_coldstart}, near-zero false alarms on analytical ORM queries \cite{alazab2022imbalanced,saito2015prauc}, and robustness against adaptive syntactic obfuscation \cite{halfond2006,demetrio2020wafamole,demetrio2021adv_waf}.

Existing industry defenses—notably OWASP ModSecurity CRS v4 \cite{owaspcrs2024} and the \texttt{libinjection} lexical fingerprinter \cite{galbreath2013libinj}—execute rapidly but misclassify legitimate Common Table Expressions (CTEs), JSON operators, and English prose containing SQL homographs, while remaining brittle against dialect-specific comments \cite{appelt2018mlwaf,wang2024obfuscated_sql}. Conversely, monolithic sequence and syntax-tree neural networks \cite{fang2018bilstm,zhang2020cnn_bilstm,tang2020sql_ast,li2021ast_gnn,guan2023bert_sqli} incur 4--18~ms single-core CPU latency, suffer from fixed-length input truncation bypasses when benign SQL prefixes push malicious clauses past 256--512 tokens, and expose AST parsers to Algorithmic Complexity DoS \cite{crosby2003algodos,davis2018redos}. Moreover, prior security ML studies frequently rely on random train/test splits that leak identical query skeletons across partitions \cite{pendlebury2019tesseract,arp2022dos_donts}.

Motivated by adaptive early-exit cascades \cite{viola2001cascade,teerapittayanon2016branchynet,bolukbasi2017adaptive,xin2020deebert} and integer quantization \cite{jacob2018quantization,gholami2022quant_survey,onnxruntime2021}, this study designs, hardens, and cryptographically audits \textbf{CASCADE-SQL}. The primary contributions of this work are:
\begin{enumerate}
  \item \textbf{Hardened Multi-Window Cascaded Proxy:} We integrate an $O(L_{\max})$ pre-parser DoS guard, a strided multi-window CNN-BiLSTM fast filter ($W=256, S=192$) that eliminates prefix-padding truncation bypasses, and a hotspot-focused canonical \texttt{sqlglot} AST + Self-Attention verifier.
  \item \textbf{Constrained Router Calibration \& INT8 Compression:} Router thresholds $(\tau_{\text{low}}^*, \tau_{\text{high}}^*)$ are optimized strictly on validation data under explicit FPR/FNR bounds and compiled into a 721.8~KB INT8 ONNX Runtime package with 20.43~ms cold-start time.
  \item \textbf{Zero-Leakage Multi-Suite \& 5-Fold Benchmark:} We evaluate across 50,460 PostgreSQL and MySQL queries (42,667 isolated AST templates), 6 SOTA baselines, 100:1 and 1,000:1 class imbalance, 2,000 hard-benign ORM queries, zero-shot cross-dialect transfer, 40,000-query iterative WAF-A-MoLE attacks, and live FastAPI/OpenTelemetry HTTP concurrency load tests.
\end{enumerate}

\section{Related Work}
Early SQLi countermeasures relied on static parse-tree comparison \cite{buehrer2005parse}, instruction randomization \cite{boyd2004sqlrand}, and formal command-token boundaries \cite{su2006essence}, whereas cloud WAF deployments standardized around regex scoring \cite{owaspcrs2024} and \texttt{libinjection} token folding \cite{galbreath2013libinj}. Subsequent ML approaches progressed from token graphs \cite{kar2016sqligot} to character/word CNN-BiLSTMs \cite{fang2018bilstm,liu2019deepwaf,zhang2020cnn_bilstm}, AST-driven GNNs \cite{tang2020sql_ast,li2021ast_gnn}, and pre-trained Transformers \cite{guan2023bert_sqli,chen2023trans_waf}. However, as summarized in Table~\ref{tab:related_work}, prior neural detectors overlook (i) template leakage across splits \cite{arp2022dos_donts}, (ii) prefix-padding evasion beyond fixed sequence lengths, (iii) iterative grey-box mutation \cite{demetrio2020wafamole}, and (iv) live serverless FinOps and concurrency constraints \cite{eismann2021serverless_cost}.

\section{System Architecture and Threat Model}
Figure~\ref{fig:arch} illustrates CASCADE-SQL deployed as an inline ASGI/TCP database proxy inside a 1-vCPU / 256~MiB serverless container fronting Cloud SQL (PostgreSQL and MySQL). Every request is traced via OpenTelemetry spans ($T_{\text{net}}, T_{\text{guard}}, T_{\text{S1}}, T_{\text{S2}}, T_{\text{DB}}$). The threat model considers an adaptive attacker capable of:
\begin{itemize}
  \item \textbf{T1 (Dialect \& Homograph Obfuscation):} Using MySQL versioned comments (\texttt{/*!50000...*/}), inline comment splitting, PostgreSQL casts (\texttt{::text}), hex/CHAR encodings, and control whitespace \cite{wang2024obfuscated_sql}.
  \item \textbf{T2 (Prefix-Padding \& Iterative Grey-Box Evasion):} Prepending $>256$~bytes of legitimate SQL clauses before appending tail SQLi, or querying the detector iteratively via WAF-A-MoLE \cite{demetrio2020wafamole,demetrio2021adv_waf} to depress Stage-1 confidence scores.
  \item \textbf{T3 (Algorithmic Complexity DoS):} Sending megabyte-scale floods or 200-depth nested parentheses to exhaust regex engines \cite{davis2018redos} or recursive-descent SQL AST parsers \cite{crosby2003algodos}.
\end{itemize}

\section{Hardened CASCADE-SQL Methodology}
\subsection{Pre-Parser DoS Guard and Bounded Strided Multi-Window Stage-1}
For an input query $x$ cleaned of null bytes, the pre-parser guard immediately blocks payloads violating $|x|_{\text{bytes}} > L_{\max} = 8192$ or parenthesis depth $\text{depth}(x) > D_{\max} = 32$ in $O(L_{\max})$ bounded time without AST allocation.

To eliminate fixed-length truncation blind spots while preserving single-window speed on normal queries ($L = |x| \le W = 256$), queries with $L > W$ are partitioned using stride $S = 192$ (64-byte overlap):
\begin{equation}
K(L) = 1 + \left\lceil \frac{L - W}{S} \right\rceil, \quad s_k = \min\big((k-1)S, \; L - W\big), \quad k \in \{1, \dots, K(L)\}.
\end{equation}
Because $s_{K(L)} = L - W$, the terminal window covers $[L-W, L)$ exactly, guaranteeing 100\% byte coverage up to $L_{\max}$ ($K \le 43$). Stage-1 (multi-scale Conv1D $k \in \{3,5\}$ + BiLSTM, 145,249 parameters) evaluates all $K$ windows in one ONNX mini-batch, yielding $p_1^{\max}(x) = \max_k \sigma(z_1(w_k))$ and localizing hotspot window $k^* = \arg\max_k p_1(w_k)$. Single-window confident queries exit immediately ($p_1 \le \tau_{\text{low}}^* \Rightarrow 0$; $p_1 \ge \tau_{\text{high}}^* \wedge K=1 \Rightarrow 1$). Multi-window hotspot alerts ($K > 1 \wedge p_1^{\max} > \tau_{\text{low}}^*$) and single-window gray-zone queries ($\tau_{\text{low}}^* < p_1 < \tau_{\text{high}}^*$) escalate to Stage-2, preventing false positives on long analytical queries while trapping tail-injected payloads.

\subsection{Hotspot-Focused Canonical AST + Self-Attention Stage-2 Verifier}
Stage-2 unwraps MySQL versioned comments and strips obfuscation comments around the query prefix and localized hotspot $[s_{k^*}-64, s_{k^*}+384)$, tokenizing via \texttt{sqlglot} into structural token IDs $\mathbf{t} \in \mathbb{Z}^{128}$ alongside a 24-dimensional AST/lexical vector $\mathbf{f}_{\text{struct}} \in \mathbb{R}^{24}$ (capturing normalized length, nesting depth, Shannon entropy, comment counts, tautologies, union-select transitions, and catalog/time-delay functions). Two 4-head Self-Attention blocks fuse with a LayerNorm-GELU structural MLP (106,177 parameters) to emit $p_2(x)$. Constrained grid optimization on $\mathcal{D}_{\text{val}}$ yields $(\tau_{\text{low}}^*=0.05, \tau_{\text{high}}^*=0.65, \tau_2=0.50)$, and dynamic UINT8 ONNX quantization achieves exact test classification parity with FP32.

\section{Zero-Leakage Dataset Protocol and Experimental Setup}
This study curates 50,460 deduplicated queries (26,836 MySQL, 23,624 PostgreSQL) normalized into 42,667 canonical \texttt{sqlglot} templates and partitioned via \texttt{GroupShuffleSplit} with verified 0\% template overlap across Train, Validation, and Test splits (Table~\ref{tab:dataset_summary}) \cite{pendlebury2019tesseract,arp2022dos_donts}. Training used an NVIDIA GeForce RTX 2050 GPU (PyTorch 2.6.0, CUDA 12.4), and CPU benchmarks used single-threaded ONNX Runtime 1.32.0. Statistical significance is assessed via exact/continuity-corrected McNemar tests \cite{mcnemar1947} and Wilcoxon signed-rank tests \cite{wilcoxon1945,demsar2006statistical}.

\subsection{Core Benchmark Performance (RQ1--RQ5)}
Tables~\ref{tab:rq1_performance}--\ref{tab:rq5_xai} and Figures~\ref{fig:latency_cdf}--\ref{fig:shap_dos} establish baseline RQ1--RQ5 performance:
\begin{itemize}
  \item \textbf{Detection \& Obfuscation (RQ1):} On the held-out test set ($N=9,920$), CASCADE-SQL achieves 0.9991 F1 (0.9998 ROC-AUC, 0.053\% FPR) vs.\ 0.8937 F1 and 28.48\% FPR for OWASP CRS v4, while detecting 99.59\% of 7-strategy adversarial obfuscations ($N=6,152$).

  \item \textbf{Ablation, SHAP \& DoS Guard (RQ4--RQ5):} Canonical comment de-obfuscation significantly boosts adversarial recall ($p = 2.48 \times 10^{-19}$), INT8 significantly accelerates FP32 (Wilcoxon $p = 4.79 \times 10^{-87}$), \texttt{shap.KernelExplainer} \cite{lundberg2017shap} confirms comment/tautology/depth features drive Stage-2 decisions, and the pre-parser guard blocks 64~KB floods 69,852.0$\times$ faster than unguarded AST parsing while preventing 100\% of 200-depth recursion faults.
\end{itemize}

\subsection{Extended Hardening Benchmarks: SOTA Baselines \& Tail-Padding Defense (Exp-1 \& Exp-2)}
To benchmark against stronger industry and neural alternatives, Table~\ref{tab:exp1_sota_baselines} and Figure~\ref{fig:sota_pad}(a) evaluate six systems trained and tested on identical zero-leakage splits. \texttt{LibInjection} executes in 0.020~ms but misses 44.67\% of held-out attacks (F1 0.6934). \texttt{TF-IDF + HistGBDT} (4.579~ms) and 2-layer \texttt{BiLSTM-Attention} (6.295~ms) degrade on obfuscated payloads (92.39\% and 97.11\% recall, McNemar $p < 10^{-34}$). A 1.38M-parameter, 4-layer \texttt{Subword SQL Transformer} matches CASCADE-SQL on adversarial recall (99.76\% vs.\ 99.63\%, $p=0.1338$), yet requires 8.197~ms mean latency ($p_{99}=18.133$~ms) and 5,401.3~KB storage, whereas hardened CASCADE-SQL achieves the highest held-out F1 (0.9990) and 100:1 PR-AUC (0.9257) at 1.729~ms mean latency in 721.8~KB.

Table~\ref{tab:exp2_padding} and Figure~\ref{fig:sota_pad}(b) expose the critical vulnerability of fixed 256-byte input truncation: appending 1,000 SQLi payloads behind $\ge 256$~bytes of benign SQL clauses drives naive truncated recall from 99.30\% down to 0.00\% (100\% escape rate). Hardened strided multi-window pooling ($W=256, S=192$) restores detection recall to 99.10\%--100.00\% across 256~B to 4,096~B prefixes.

\subsection{Cross-Dialect Transfer, Hard-Benign ORM Stress \& 5-Fold Stability (Exp-5 \& Exp-6)}
Table~\ref{tab:exp5_cross_dialect_orm} reveals an important asymmetric zero-shot transfer phenomenon: training exclusively on MySQL transfers zero-shot to authentic PostgreSQL syntax at 0.9974 F1 (99.48\% recall), whereas PostgreSQL-only training achieves 0.9865 ROC-AUC on MySQL but 53.99\% fixed-threshold recall due to unseen MySQL-proprietary versioned comments (\texttt{/*!50000*/}) and XML functions—confirming the necessity of multi-dialect canonical AST training. On 2,000 unseen Hard-Benign Modern ORM queries (CTEs/windows, PostgreSQL \texttt{JSONB}, English SQL-homograph prose, and multi-quarter \texttt{UNION ALL} reports), OWASP CRS v4 and LibInjection suffer 80.0\% and 55.0\% FPR, whereas CASCADE-SQL achieves \textbf{0.00\% FPR} (0/2,000 false blocks) and 0.9927 mean PR-AUC under 1,000:1 extreme class imbalance \cite{saito2015prauc}.

Finally, 5-fold group-isolated cross-validation across all 50,460 queries (Table~\ref{tab:exp6_5fold_cv}, Figure~\ref{fig:cv_surf}) confirms tight variance (0.9989 $\pm$ 0.0002 F1; 0.0006 $\pm$ 0.0005 FPR) and flat hyperparameter sensitivity across 100 $(\tau_{\text{low}}, \tau_{\text{high}})$ grid configurations (F1 $\in [0.9986, 0.9990]$).

\section{Discussion, Limitations, and Conclusion}
Hardened CASCADE-SQL bridges the gap between sub-millisecond lexical filtering and deep syntactic verification for serverless cloud databases. Three practical boundaries remain for future work: (i) stored second-order SQLi where tainted data executes internally without wire-level syntax anomalies, (ii) encrypted TLS/binary wire-protocol parsing inside sidecar proxies (e.g., Envoy/Rust WASM filters) to eliminate JSON/HTTP serialization overhead observed at high concurrency, and (iii) continual threshold adaptation for emerging proprietary SQL extensions. Backed by 100\% real execution logs and SHA-256 verification across all 13 tables and 8 figures, CASCADE-SQL offers a rigorous, production-ready defense for cloud-native DBaaS workloads.
